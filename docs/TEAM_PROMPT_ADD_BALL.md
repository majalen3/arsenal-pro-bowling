## 3. Invariants (non-negotiable)

1. **No invented specs.** A field is either sourced (chip shows source + date) or shows **"spec TBD"**. The engine never runs on a guessed RG, differential or cover type.
2. **Provenance on every value**: `manufacturer` (fetched maker page, URL + fetch date), `usbc` (approval date from the USBC list), `catalog` (derived third-party catalogue, named), `user` (typed by the owner), `model` (engine output). Use `chip()`.
3. **The user confirms before anything is saved.** A lookup result is a proposal, never an auto-save. Fuzzy matches are never auto-accepted.
4. **Engine:** `simulatePath`/`analyze` unchanged (`node tests/engine_equivalence.mjs` = 0 mismatches). The 2-D model is the engine; the 3-D engine stays behind `cc3d` (off).
5. **Server-side lookup only** (browser CSP `connect-src` allows only the Render API). The API fetches **only allowlisted manufacturer hosts**, https only, redirects re-checked against the allowlist, size/time caps, `robots.txt` respected, one identifying User-Agent, cached. No retailer scraping, no logins, no credentials, no PDFs/files committed to git.
6. **No raw third-party files in git.** `ball_specs.csv` (bowlingballvideos.com) stays out of the repo; only the derived `js/data/spec_catalog.js` (prov `catalog`) is committed, regenerated by `tools/build_spec_catalog.py`.
7. **Privacy:** `/api/me` export/delete covers every table holding user data. `spec_cache` is global public maker data with **no device id** — keep it that way (DECISIONS #14).
8. **UI:** Honey Badgers tokens only (no new hex), 360 px first, 44 px targets, coach copy ≤ 2 sentences starting with a number or ball name, CSP `script-src 'self'`, no inline scripts/CDN/eval. Free app: no ads, no purchase links.
9. **No messages to anyone.** Tests never write to the production DB.

## 5. Feature definition

1. **Type a name** (brand optional). Client matches against the derived catalog (`spec_catalog.js` + app `data.js`) with `norm()` + alias index + token/edit-distance scoring. Exact → one card; fuzzy → up to 6 candidates; none → "Look up on the maker's site".
2. **Lookup** (`GET /api/spec-lookup?brand=&name=` or `?url=`): discovery via the brand's allowlisted sitemap or URL template → fetch → parse labelled spec block (RG, Differential, Intermediate/Mass bias/PSA, Coverstock, Cover type, Finish/grit, Core, Symmetry, Release date, per-weight RG/Diff table) → cache → return found fields + `sourceUrl` + `fetchedAt`. Missing = absent (shown "spec TBD").
3. **Confirm sheet:** every field with chip; weight picker (per-weight values when the maker publishes them); conflicts (catalog ≠ maker) shown side by side, maker wins by default; user can correct a field (chip becomes `user`).
4. **Engine card:** same release (owner speed/rev, tonight's pattern preset) for the new ball and the Rattler Big Bite: skid/hook/roll lengths, breakpoint (board @ ft), entry angle, strike %, model line (target/aim). Compute time shown in dev; < 1 s on a phone.
5. **Grid placement:** oil level × shape cell, overlap with existing bag balls, holes it fills, holes that remain.
6. **Save** → `ownedBall.created` with `spec` (fields + per-field provenance) and `weight`. The ball then resolves everywhere via `js/cc/cats.js` (rank, bag, Tonight).

## 8. Risks

| Risk | Mitigation |
|---|---|
| Maker site layout changes | Parser per layout family + fixtures; return `not-found` instead of partial guesses; log in UX_CYCLE_LOG. |
| Site blocks fetches (Motiv 403) or TLS issues (www.rotogrip.com, www.900global.com) | Mark brand `unsupported` with a clear message; catalog + manual entry still work. Never bypass blocks. |
| Catalog vs maker conflicts (e.g. per-weight values) | Show both, default to maker, record weight. |
| Load on maker sites | Cache 30 days, sitemap cache 24 h, per-IP limit, robots.txt respected. |
| SSRF via `?url=` | Host allowlist, https only, DNS → refuse private ranges, manual redirects re-checked. |
| Engine misuse on partial specs | `specOK` gate; card says what is missing. |

## 9. Improvement loop (run continuously after AB0–AB4)

Each cycle (aim: 1 cycle per session):

1. **Audit** — run the gate; read the last 3 UX_CYCLE_LOG entries; check `/api/spec-lookup` misses (names that returned `not-found`/`unsupported` in testing).
2. **Research** — RS picks the top backlog item; documents the source (maker URL, layout) in `ARSENAL_MANAGER_RESEARCH.md`.
3. **Build** — smallest change that moves one target; tests first for parser/matching.
4. **QA** — full gate §7 + live verification.
5. **Ship** — path-scoped commit, rebase, push; verify Render deploy + Pages.
6. **Log** — UX_CYCLE_LOG entry (what, numbers before/after, screenshots), DECISIONS entry when a rule changes, update this backlog.

**Backlog (ordered; update each cycle):**
1. Motiv, Roto Grip, 900 Global, Columbia 300, Ebonite, Track discovery routes (allowlisted, robots-respecting) — currently unsupported/unverified.
2. Storm discovery for names that don't follow the `storm-<slug>-bowling-ball` template (use the brand page search, not guesses).
3. Spec-sheet PDFs (Storm "Tech Data", Brunswick "Info Sheet") as a second source when the HTML lacks a field — text extraction server-side, nothing stored but parsed fields.
4. USBC approval list lookup (approval date) as `usbc` provenance for every added ball.
5. Catalog refresh tooling + diff report (catalog vs maker conflicts), e.g. Storm Mix listed as urethane in the catalog.
6. Per-weight engine run when the owner records a different weight per ball.
7. Edit/retire an added ball; re-lookup button refreshing a stale cache (> 1 year).
8. Tonight ranking explanation for added balls ("new" badge until first logged shot).
9. 3-D engine comparison behind `cc3d` once that engine is validated.
